# large-price-model — successor spec v1

Spec for the next phase of the project. The initial phase — a causal decoder transformer over 15-minute SPY bars — closed on 2026-08-26 (`reports/phase-h-close.md`). It established two facts about the model's output.

First, the technique runs end-to-end and produces a small improvement over baselines that read only the target's own history: log-loss 3.180 against a tuned MLP at 3.212, GRU at 3.219 and linear at 3.256, five seeds each (`reports/baseline-convergence.md`, corrected 2026-09-27 from the earlier "3.180 against 3.333"). Those baselines read only SPY's bucket history; the spec-defined target-only ablation, which would say what the other nineteen channels add, was never run on the normalized data.

Second, the improvement decomposes precisely. Every next return can be split into two parts: a conditional mean — the drift the input features predict — and a conditional variance — the spread around that drift, also conditioned on the input features. The model captured the conditional variance. It did not capture the conditional mean. A rule that reads only the mean of the model's output captures none of the log-loss gain.

The null on the mean is the expected outcome for this specific target at this specific horizon. Fifteen-minute SPY bars sit in a structural gap. Sub-second horizons are dominated by order-flow dynamics and latency arbitrage. Daily and longer horizons carry behavioral under-reaction, factor rotations, and credit cycles. Fifteen-minute bars on a deeply liquid, heavily arbitraged benchmark ETF live in a regime where any publicly observable cross-asset signal is rapidly assimilated by a large ecosystem of quantitative participants. Under that condition the noise-to-signal ratio for the first moment is extraordinarily high. The failure to predict the mean is consistent with the arbitrage saturation of this specific market microstructure — not with a universal market-efficiency claim, and not with an architectural failure.

The successor is not a bigger version of the initial phase. It is three open research questions the initial phase's finding brings into focus. All three are equally load-bearing. Each is the shape it is because the underlying question has that shape, not because of a preferred ordering.

## Question 1 — how do we get the data we need, and what data is that?

The initial phase used 15-minute SPY bars from Alpha-Vantage because that is what was on hand. The successor cannot inherit that shortcut. The shape of the data is part of the model's design — the structure the data has determines what the model can learn to represent. A model given 15-minute bars cannot learn microstructure. A model given a single instrument cannot learn cross-sectional structure. A model given only trades cannot learn from quote imbalance. Every choice at the data layer forecloses or opens a category of hypothesis the model can then test.

The question splits into four sub-questions with no fixed answer.

**Resolution.** Tick, sub-second, second, minute, or coarser. Lower resolution is cheaper to store and easier to model but averages away the finer structure. Higher resolution multiplies storage cost and pre-processing complexity but preserves the microstructure the model would need to learn from. There is no universal right answer — the resolution follows the hypothesis.

**Instrument set.** Single-name equities, sector ETFs, index components, futures, options, cross-asset panels. Each opens a different set of hypotheses. A single instrument tests whether the model finds temporal structure at all. A panel of related instruments tests whether cross-sectional relationships are learnable. A cross-asset set tests whether the model finds transfer between markets. The set is a research choice, not a scope decision.

**Vendor.** Databento, Polygon, direct exchange feeds, historical CSV archives. Pricing, coverage, quality, and licence terms all vary and all change year to year. The choice depends on which resolution and instrument set the research picks, and on which vendor's licence permits the kind of storage the archive requires. Vendor is a live cost line, not a one-time decision.

**Storage.** The data has to live somewhere the research can actually reach. That means an archive — every byte we pull, kept forever, addressable by exactly what we pulled and when. It also means a working store — the same data reshaped for fast queries at the resolution and horizon a given experiment needs. Format (parquet, arrow, columnar databases like ClickHouse or DuckDB, purpose-built tick-store libraries) trades query speed against ingest speed against disk footprint. Provenance discipline from the initial phase — every downstream artifact stamped with the data hash it consumed — must carry through so that any result is reproducible to its exact input bytes. The archive-plus-working-store shape is itself a design decision to be made, not a background assumption.

First pass: a written comparison matrix of (resolution × instrument-set × vendor × storage), with the hypothesis each cell would let the model test and the concrete cost of standing that cell up. That document is what unblocks the choice of the actual first pull.

**On sequencing.** A competent alternative frame says: before changing what data the project consumes, diagnose the existing model on the existing data. Retarget it, probe its internals, run synthetic controls (see Question 2), and let the diagnosis point at what data actually needs to change. That frame is defensible. It runs cheap, it produces publication-value findings from the existing corpus, and it avoids committing to a large data acquisition before the questions the data would answer are sharpened.

This spec takes the opposite position: the data comes first. The reason is structural. The shape of the data determines what the model can learn to represent. A diagnostic pass on a corpus that averages away the microstructure will confirm that the microstructure was averaged away, and will not open the questions only richer data can answer. Both workstreams still run — Question 2's diagnostics on whatever data is on hand, Question 1's acquisition on its own schedule — on the theory that findings from each refine what the other asks for.

## Question 2 — what does the inside of the model need to look like, and how do we get it there?

The initial phase closed with a specific finding: the transformer improves the distribution's shape without moving its mean. That improvement lives somewhere inside the model — in some subset of layers, some subset of attention heads, some direction in the internal state. Question 2 asks two related things about that. First, what does that internal state need to look like for the model to actually be useful. Second, how do we deliberately shape it that way — with what techniques, applied when, checked how.

The frame that makes this tractable is the same one used to study language models. A transformer's internal state at each layer is a high-dimensional vector. Over a corpus, the vectors form a distribution. The structure of that distribution — what clusters, what separates, what varies linearly along what direction — is what carries the model's usefulness. A language model does not know "computer" and "science" as two disjoint tokens; it knows "computer science" as a region in the internal state that a downstream reader can pick out. The same question applies to a price model: what regions or directions has it built that a downstream reader could actually use, and if the answer is "not the right ones," how do we make it build the right ones instead.

This question sits at the edge of what is well-understood publicly. Techniques exist — linear probes, sparse autoencoders, activation steering, representation engineering, contrastive geometry — and their maturity varies. Some are ten years old and stable. Some are recent enough that their trade-offs are still being worked out. Track 2 is partly about applying what is known and partly about learning what is known well enough to apply it.

The settled-technique end of Question 2 has three worked examples. Each answers a different question about what the model has built inside itself, and each is cheap enough to run against every layer of a trained checkpoint.

**Layer probes.** For each layer, take the internal state at a snapshot of contexts. Fit a linear regression from that state to a small set of target scalars — next-bar realized variance, realized range, next-bar sign. Compare the fit against the same probe run on the raw input features alone. A layer that adds signal for a target has learned to encode something about that target beyond what the input carries directly. Reading the fit as a function of layer number tells us where in the model the improvement is concentrated.

**Regime axes.** Label a corpus of contexts by regime (low-vol vs high-vol; quiet vs event-day; session opening vs mid-session vs close). For each layer, fit a linear classifier on the internal state predicting the regime label. A clean axis of separation means regime is a learned concept the model holds. A muddled one means the model has not internally distinguished the regimes, even when its output distributions differ across them.

**Context clusters.** Take a set of contexts, run each through the model, and collect the output distributions. Cluster the contexts by how similar their output distributions are. Then ask what the clustered contexts share in their inputs — and, more interestingly, what they share that the inputs do not obviously carry. When two contexts with different surface features produce similar output distributions, the model has built an internal association the raw features do not encode.

Those three probes are examples of the settled-technique end. They map what the model represents against a small number of pre-chosen targets. That map is useful; it does not exhaust the workstream. It does not tell us how to change what the model represents. It does not surface structure the pre-chosen targets miss. Both of those questions belong to the newer end of the technique space — sparse autoencoders, activation steering, representation engineering — where the tools are still being worked out and any application of them here is itself research. That map answers whether the distributional improvement from Phase H is coming from something specific and namable, or from a diffuse effect no downstream reader can catch. If the map shows specific structure, the next question is how to shape more of it — where the newer techniques (sparse autoencoders, activation steering) become the work.

Beyond the probes there are **retraining experiments** — take the same architecture and change what it is trained on or trained to predict — that answer questions the probes cannot.

**Variance retargeting.** Take the same architecture and retrain it to predict a continuous variance metric directly instead of a bucket over the return. Candidate targets: the future 15-minute range (high minus low), the squared return, the log-variance. Score with a strictly proper rule for continuous distributions (CRPS), and compare against a GARCH(1,1) baseline fit on the same window. If the architecture beats GARCH on volatility forecasting, that quantifies the Transformer's edge directly instead of inferring it from the categorical model's distribution shape.

**Synthetic controls.** Generate a synthetic return series with a known persistent directional signal — a stationary autoregressive process with a known coefficient, or a hidden Markov switching series — while preserving the cross-asset covariance structure of the real data. Train the exact same architecture on this synthetic data. If the model recovers the known coefficient, the architecture is sound and the null on the real SPY mean is genuinely due to the target's structural unpredictability. If the model fails on synthetic data, the null on SPY is at least partly architectural — insufficient sequence length, wrong positional encoding, wrong optimization dynamics, or wrong loss.

**Systematic ablation.** Rather than ask what works, ask what fails. Remove input categories one at a time — a text source, an instrument, a horizon, a feature channel — and measure the drop in log-loss or CRPS. The categories whose removal costs the most are the most informationally relevant. The categories whose removal costs nothing are redundant, no matter what theory says they should carry. The pattern in what matters and what does not is the finding, independent of any absolute performance number. See `text-market-experiments-v1.md` Program 7 for the fuller research-program version of this experiment against arbitrary text categories.

Question 2 and Question 3 overlap. Question 3 asks which external techniques transfer; Question 2 asks how to shape the model's internal state. The overlap: some transfers from Question 3 (contrastive pretraining, masked pretraining) work precisely by shaping the internal state. The distinction: Question 3 is about where a technique comes from; Question 2 is about what the technique does inside. The boundary between them will get clearer as findings from each land.

## Question 3 — which metaphors from other domains transfer to price data, and how?

Attention over words came from database keys and queries. Convolution over pixels came from biological visual cortex. Diffusion in image generation came from thermodynamics. Each of those moves worked because the projection between the source domain and the target domain preserved enough of what mattered. Not every metaphor works — the mapping has to carry the right structure across the projection. A system built on a bad metaphor is computationally still a system; it produces outputs; but the outputs do not correspond to anything in the target domain that a downstream reader can use.

The question this workstream asks is which metaphors, from any domain, transfer to price data — and what the pattern in the ones that transfer tells us about what price data actually is, viewed as a computational object. Language and vision are the obvious first sources because their techniques are best documented and most transferable. The question is broader than either.

Here is the framing that matters. What a large language model does, operationally, is simulate a language user. The model is trained on the artifacts of language use — text corpora — and a downstream layer on top wraps its predictions into behavior that reads as coming from a competent participant in a conversation. A price model applied the same way is simulating a market participant. The market's digital form — bars, ticks, quote streams — is the artifact of what used to be a room full of people shouting at each other, making hand signals across a trading floor, negotiating meaning through price. That yelling was language. It was meaning-construction, belief-exchange, translation between what one participant knew and what another believed. The floor is gone; the artifact remains. What a price model learns to simulate, if it learns anything at all, is the participant in that conversation.

That framing changes what transfer looks like. The successful language-model tricks (masked pretraining, contrastive learning, retrieval, patch embeddings, mixture of experts, chain-of-thought decoding) are worth trying because their bottlenecks in text have plausible analogs in a price stream. But the deeper question is which projections between spaces preserve what matters. A time-series problem is not a text problem, but both are sequential; both have local structure and long-range dependence; both admit ambiguity in the tokens themselves; both are records of participants doing something. The metaphors that transfer are the ones whose projection preserves those shared properties without forcing the target domain to pretend it is the source.

First-pass candidate transfers, each one sprint or a small cluster. Each is a hypothesis about a specific mapping.

- **Masked pretraining (from language).** Mask fifteen percent of bars, predict them. Hypothesis: filling in contextual holes forces a richer representation.
- **Contrastive pretraining (from language and vision).** Pair adjacent windows against random windows. Hypothesis: local temporal structure has a learnable geometry. See `text-market-experiments-v1.md` Program 8 for the fuller version — self-supervised alignment between text and prices as a CLIP-style foundation objective, trained before any supervised target.
- **Retrieval augmentation (from language).** At inference, retrieve K similar historical windows and condition on them. Hypothesis: the model's answer improves when told what past regimes it matches.
- **Patch embeddings (from vision, via PatchTST).** Aggregate consecutive bars into one token. Hypothesis: one-token-per-bar is not the right granularity.
- **Mixture of experts (from language).** Route the FFN by regime. Hypothesis: specialists per condition beat one dense model over all conditions.
- **Chain-of-thought decoding (from language).** Force the model to emit intermediate scalars before its final distribution. Hypothesis: making the model "reason out loud" improves what it puts on the target.
- **Continuous parametric output (from broader distributional ML).** Replace the categorical bucket head with a parametric distribution — a skewed-t, a mixture of Gaussians, a normalizing flow. Score with a strictly proper continuous rule (CRPS) instead of log-loss on discrete buckets. Hypothesis: the categorical head's coarse histogram throws away information the model has learned to express; a continuous head lets that information land.
- **Multi-scale processing (from vision, pyramid networks).** Process the same data at multiple resolutions (5-minute, 15-minute, hourly, daily) with a learnable gating mechanism that selects the relevant scale for each prediction. Hypothesis: market dynamics are multi-scale and a fixed window size forecloses signal at other scales. See `text-market-experiments-v1.md` Program 6 for the fuller research-program version.

Those six are language and vision because those are the domains whose techniques are best documented today. The workstream is not limited to them. Any technique from any domain whose bottleneck maps to something a price model faces is a candidate — diffusion from physics, graph attention from chemistry, contrastive audio pretraining from speech, world-models from reinforcement learning. What matters is the mapping: its correctness, its preservation of structure, the degree of ambiguity it tolerates.

The output of Question 3 is a growing set of tested metaphors, each marked as transferred / did not transfer / transferred only under a specific regime. The pattern in what transferred and what did not is the workstream's real finding. It is what tells us — as a matter of empirical fact rather than theoretical guess — what price data actually is, in terms of the computational objects other domains have already learned to model well.

## Constraints carried from the initial phase

- No hosted trackers. Local files and self-hosted tools only. Ratified 2026-08-13.
- Signal-Driven Development discipline. Every task is a sprint card. Every code path emits typed signals. Every sprint closes with a review.
- Held-out data is sacred. The initial phase's held-out window (2024-01 through 2025-06) has one look remaining. The successor declares its own held-out window and its own look budget in a Decision before any track-2 or track-3 result is measured against it.

## Companion specs

Longer-horizon proposals that build on the three questions above land as their own documents so they stay at architecture altitude without diluting this spec's question altitude.

- **`text-integration-v1.md`** — arbitrary-text integration as a further phase. Extends Q1's data question to text corpora (books, social media, science, government, cultural artifacts). Deepens Q3's retrieval bullet into a full retrieval-plus-cross-attention architecture with universal embeddings, temporal decay, and latent-regime compression. Q2's interpretability techniques apply directly to the retrieved-document attention weights. Sits further out on the horizon than the three co-equal questions here; becomes active work when the earlier phase's findings point at it, or sooner if the operator judges text is the more valuable question.
- **`text-market-experiments-v1.md`** — eight research programs the text-market architecture enables. Each is a self-contained program with its own hypothesis: information diffusion latency, counterfactual price formation, semantic state inversion, topological regime discovery via text embeddings, information entropy divergence as a volatility indicator, learnable temporal granularity, systematic ablation, self-supervised alignment. Three of these have direct hooks in this spec (multi-scale in Q3, systematic ablation in Q2, self-supervised alignment deepens Q3's contrastive bullet); the other five require the full text-integration stack.

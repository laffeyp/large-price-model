## Why v0.2 exists

Sprint 007 attempted to tighten `_parse_type`'s permissive `_check_str` fallback for unknown type strings (per `reviews/sdd-discipline-check-round-1.md` §3). The tighten surfaced a v0.1 defect: `CAPACITY_SWEEP_COMPLETED.points` was typed as `list<dict<size_usd:float, sharpe:float, sharpe_se:float>>`, which the Layer-2 vocabulary in `signals/0.1-rationale.md` has no syntax for. `dict<K,V>` names one key type and one value type; the malformed declaration crams three named fields with types into the K/V slot. Sprint 007 halted with `vocabulary_change_required`.

Two paths were considered:

- **Downgrade to `list<dict<str, float>>`.** Loses the per-field type distinction the vocabulary session declared. Field names move to the tag's `note`. Rejected — erases information the vocabulary intentionally carried.
- **Extend the parser with a `struct<name:type, ...>` composite.** Preserves per-field types. Aligns the parser with the vocabulary session's intent. Requires a v0.2 lock so the corrected declaration lands under proper hard-rule-12 evolution. **Chosen.**

Sprint 008 authored the parser addition (`_check_struct` + `_parse_type` branch, five new tests). Sprint 009 (this lock) declares the type in v0.2.

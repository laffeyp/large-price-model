# Vocabulary v0.4 rationale

**Locked:** 2026-08-13.
**Delta from v0.3:** one tag removed — `WANDB_UPLOAD_FAILED`.

## What changed

`WANDB_UPLOAD_FAILED` is deleted from the tag list and from every `allowed_set` (train, eval, simulate) it appeared in. Tag count drops from 56 to 55.

## Why

The tag existed only to record failed uploads to Weights & Biases, a third-party hosted experiment-tracking service. The project no longer uses Weights & Biases and never will. The tag has no emit sites anywhere in `src/`; deleting it does not orphan any code.

The training loop's SDD JSONL trace at `logs/{run_id}/signals.jsonl` already captures every scalar that would have gone to W&B: `TRAINING_STEP_COMPLETED` per step (train_loss, lr, grad_norm, throughput_tokens_per_sec) and `CHECKPOINT_WRITTEN` per checkpoint (val_nll, val_ece, val_brier, val_rps, val_dir_acc, val_top1, val_top3). Downstream plotting reads the trace directly.

## What is preserved

v0.3.json remains on disk at `signals/0.3.json` per hard rule 12. Any historical trace file that recorded `WANDB_UPLOAD_FAILED` under v0.3 stays interpretable via the v0.3 loader.

## What is not changed

No allowed_set constraint added or renamed. No other tag altered. No payload type changed. The `evidence_required` constraints, `forced_next` rules, and `expected_count` cadences all carry through unchanged.

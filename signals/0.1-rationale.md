## Intent and scope

This vocabulary types the signals a Price-Space LLM v1 pipeline emits. The pipeline reads 15-minute multi-channel market state, embeds each bar as a `d_model` vector, trains a causal decoder transformer to predict a 32-bucket vol-normalized forward return distribution, and runs a cost-aware simulator over a chronological holdout (2024-01 through 2025-06). Success gates and pre-registered ablations live in `specs/product-spec-v4.md`; module boundaries and interfaces in `specs/technical-architecture-v4.md`.

Bounds: this vocabulary covers ingestion, alignment, feature computation, tokenization, embedding, model training, evaluation, cost calibration, and simulation. It does not cover live paper trading, RL policy training, LOB tokens, or cross-instrument multi-target training — those are v2/v3 items whose vocabulary extensions arrive as `NEW_TAG_PROPOSED` entries under a v0.2 lock.

## Per-layer decisions

### Layer 0 — Ontology (31 entities)

**Round 1 → Round 4 trajectory.** Round 1 drafted 31 entities, then resolved cross-document polysemies inside the JSON as "distinct" verdicts — a violation of commitment #3 (workers cannot invent vocabulary). Round 2 responded by inventing seven non-canonical proposal types — the same failure at the meta-vocabulary level. Round 3 recast to the eight canonical types PRINCIPLES.md names, moved pre-lock entity additions from `proposals.json` into `entity_implied_but_unnamed.flags[]`, and moved forward-commitments to BLACKBOARD `## Deferred`. Round 4 corrected two remaining layer-dependency-order violations: `NEW_TAG_PROPOSED` for a Step-2 tag filed at Step 1, and four Layer-6-forward flags filed under a Step-1 halt mechanism. Every round's disposition is recorded in the four review files under `reviews/` and the BLACKBOARD `## Surfaced for review` entries dated 2026-08-09.

**Three merges accepted (P-001/P-002/P-003).** `Baseline + Ablation → Model` (nine variants distinguished at Layer 2 by `run_kind`), `Distribution → Prediction` (Distribution names the object, Prediction the role), `SpreadCalibration + KappaCalibration → CostCalibration` (one Layer-6 operator writing to one directory, read as one precondition by the Simulator).

**Six flags stamped inline.** Bucket (implied by `bucket_stats.json` schema); MetricSnapshot (kit-pattern adoption from TECHNIQUES.md §2 Data science — explicit acceptance, not implicit); Split (invariant #2 anchor); Session (dually classed at Layer 0 and Layer 3 — the interior span between two SessionBoundary edges); ExperimentConfig (standalone confirmed, one-to-many with TrainingRun via `config_hash` FK; fold-into-TrainingRun rejected); Source (runtime-grammar anchor for the mcp_av → polygon fallback chain the earlier review flagged as absent).

**Removed inline.** IngestionCall (event, not entity; two Layer-1 tags emerge at Step 2); Sprint (category error — noun of AGENTS.md not of the running program; the delete-and-check test: dropping Sprint loses no Layer-1 referent); Embedder/Bucketizer/Normalizer as Layer-0 seats (operators, reclassified to Layer 6; Layer-0 seats reassigned to MarketStateToken/BucketStats/NormalizerState respectively — the pattern is consistent, the mechanism differs: for two the seat is frozen fit-state, for one it is runtime output).

**Bar broadened.** From "target instrument" to "any Symbol on the canonical UTC grid" — matches how tech-arch §4.2's channel table actually uses the word. Target bars and context bars share schema and grid; the target/context distinction rides `channel` and `target_symbol` fields at Layer 2.

### Layer 1 — Lexical (46 tags in 14 categories)

**Categories align with pipeline stages, not modules.** Per TECHNIQUES.md §1 #5 and Trading System precedent: `session`, `probe`, `ingest`, `align`, `trading_session`, `feature`, `tokenize`, `embed`, `config`, `train`, `evaluate`, `calibrate`, `simulate`, `testlook`. The four kit strata (event/ambient/summary/incident) are orthogonal — every tag carries both a category and a stratum.

**SESSION_INIT / SESSION_COMPLETE.** Kit-canonical anchors per foundation 01 and the wordcount example. `run_kind` field on SESSION_INIT distinguishes six process kinds (probe / align / calibrate / train / eval / simulate) — the `align` value was surfaced at Step 4 when Layer 3's `align_run` needed a parent condition, and back-propagated to Layer 1 per BOOTSTRAP §"Dependency structure" loop-back discipline. TRAINING_RUN_STARTED / EVAL_RUN_STARTED / etc. were considered and dropped — SESSION_INIT with `run_kind` covers the process-lifecycle role, and adding nested boundary tags for every kind would be ceremony. Two kinds *do* have distinct domain-lifecycle boundary pairs (ALIGNMENT_RUN_STARTED/COMPLETED, SIM_RUN_STARTED/COMPLETED) because their internals form a meaningful phase with persistent attributes that would otherwise be re-parsed from SESSION_INIT on every downstream read.

**TRADING_SESSION_STARTED / TRADING_SESSION_ENDED as the Layer 3 dual.** Session entity dually classed. The two tags are the Layer 1 face of the Layer 3 session stratum — same object, different layer's view.

**Simulate category is the largest (9 tags).** BAR_PROCESSED, PREDICTION_EMITTED, DECISION_MADE, POSITION_OPENED, POSITION_CLOSED, TRADE_LEDGERED, SIGNAL_DROPPED, SIM_RUN_STARTED, SIM_RUN_COMPLETED. Matches the tech-arch's most-detailed section (§11 simulator). Per BOOTSTRAP Step 2 halt condition: no entity produced more than 5 tags (the halt threshold); the widest is Simulator itself as a Layer-6 operator, and its emissions distribute across sim/testlook/trading_session categories.

**Seven passive entities.** Symbol, Channel, Split, Feature, Window, Model, Embedder produce no Layer-1 tags this pass. Their identity is referenced by other tags' payloads via foreign key (Symbol as `target_symbol`, Channel as `channel`, Split as `split`, Feature as the per-tag emission subject) rather than being emitted about. Recorded in `signals/0.1.json § passive_entities_no_tags_this_pass` for the halt-condition confirmation.

### Layer 2 — Payload (46 tags typed)

**Type vocabulary.** `str`, `int`, `float`, `bool`, `sha256`, `path`, `date_iso`, `datetime_utc`, `uuid`, `enum<VALUES>`, `entity_ref<Layer-0-entity>`, `list<T>`, `dict<K,V>`.

**Foreign-key resolution.** 39 FK candidates identified across all tags — every field whose semantics names a Layer-0 entity by identity (symbol, target_symbol, source, from_source, to_source, channel, channels, bucket_id, split, regime_label, trade_id). 39/39 resolved to `entity_ref<X>` or `list<entity_ref<X>>`. Rate 1.000, above BOOTSTRAP Step 3's 0.70 threshold.

**Opaque identifiers excluded from FK count.** `run_id`, `config_hash`, `git_sha`, `data_hash`, `sha256`, `commit_sha`, `revision_id`, `checkpoint_step`, `cost_calibration_run_id`. These are values, not references to Layer-0 entities. `run_id` in particular spans probe/calibrate/train/eval/simulate lifecycles that each mint their own — Step 6 may propose a broader `Run` entity to unify; recorded as forward-commitment.

**Enums enumerated explicitly per field.** `run_kind ∈ {probe, align, calibrate, train, eval, simulate}`, `direction ∈ {long, short, flat}`, `verdict ∈ {accepted, dropped, renegotiate}`, `n_buckets ∈ {16, 32, 64}`, `context_len ∈ {64, 128, 256, 512}`, `dropped_reason ∈ {same_direction_position_held, hysteresis_below_flip_threshold}`, per-tag `reason` enums for CHANNEL_REJECTED / SOURCE_FALLBACK_TRIGGERED / AS_OF_JOIN_MISS / DECISION_MADE.

**Validator-extras posture: strict.** Per WORKING_AGREEMENT.md § Vocabulary discipline. Any payload field beyond the schema raises at the emit call. Not Trading System's documentation-only posture.

### Layer 3 — Session (4 strata)

**Four strata declared.** `process_session` (outermost, SESSION_INIT/SESSION_COMPLETE), `align_run` (nested when `run_kind == 'align'`, ALIGNMENT_RUN_STARTED/COMPLETED), `sim_run` (nested when `run_kind == 'simulate'`, SIM_RUN_STARTED/COMPLETED), `trading_session` (nested within align_run or sim_run, TRADING_SESSION_STARTED/ENDED).

**Framing inferred vs documented.** Three of four strata (`process_session`, `align_run`, `sim_run`) inferred from tag boundaries — the specs do not use the word "session" for these. `trading_session` documented in tech-arch §5 (26 bars at 15-min RTH). Recorded in `sessions._framing_inferred`.

**Nesting declared explicitly.** align_run and sim_run parent process_session; trading_session parents whichever domain-run wraps it. Persistent attributes at each level; downstream reads look up-hierarchy for context rather than re-parsing SESSION_INIT on every per-bar tag.

### Layer 4 — Temporal (31 invariants)

**Cadence coverage.** Every ambient tag has a cadence invariant (BOOTSTRAP Step 5 halt condition). 10 cadence rules cover all 10 ambient tags: INGESTION_CALL_ISSUED (≤75 req/min per Source per token bucket), INGESTION_CALL_CACHED (unbounded), ALIGNMENT_ROW_EMITTED / BUCKET_ASSIGNED / MARKET_STATE_TOKEN_EMITTED (one per bar), FEATURE_COMPUTED (one per feature/channel/timestamp), WINDOW_SAMPLED / TRAINING_STEP_COMPLETED (one per step), BAR_PROCESSED / PREDICTION_EMITTED (one per bar in sim_run).

**Window and pairing rules.** 3 windows (POSITION_OPENED → POSITION_CLOSED within sim_run; TRADING_SESSION_STARTED → TRADING_SESSION_ENDED within one calendar day; SESSION_INIT → SESSION_COMPLETE within process budget). 8 pairing invariants (session boundaries 1:1 per run_id; positions 1:1; artifact-writing pairs 1:1; cost calibration 1:2 (one fit → two files)).

**Forbidden_after and eventually_must.** 3 each. Notable: TEST_LOOK_BUDGET_EXHAUSTED is terminal within a vocabulary version; only a version bump resets the budget. This mirrors the pre-commit hook's structural refusal per tech-arch §13.

### Layer 5 — State-Transition (27 rules)

**Sparse graph per BOOTSTRAP guidance.** Terminals per session stratum (4), forced_next for the failure path (CONFIG_VALIDATION_FAILED → SESSION_COMPLETE, 1), pairing_ordering for the pairs Layer 4 already declares (12), allowed_set per session stratum and per run_kind at process_session level (10).

**Cross-process pairing.** SIM_RUN_STARTED depends on prior CHECKPOINT_WRITTEN (loads model weights) and prior COST_CALIBRATION_FITTED (reads spread_scaler and kappa artifacts). These are cross-process rules enforced by artifact existence, not by within-session ordering.

**Reachability and cycle checks.** Every one of the 46 tags reachable from SESSION_INIT via one of the six run_kind allowed_sets. Named cycles are session-boundary open/close pairs plus the training loop's step-repeats-within-epoch pattern (bounded by fixed step budget); no unnamed cycles.

**Special case: TEST_LOOK_BUDGET_EXHAUSTED.** Enforced two ways — runtime refusal inside a simulate/eval process_session that attempts to touch held-out data beyond budget, plus a pre-commit hook that fires outside any process_session frame. The Layer-5 graph treats runtime refusal as the emission site.

### Layer 6 — Runtime / Operator (24 operators)

**P-015 commitment fulfilled.** The BLACKBOARD Deferred entry (round-3 recast of round-2 P-015) named seven operators to populate at Step 7: IngestionClient, AlignmentJoin, SourceFallback, TrainingLoop, Simulator, plus the operator-side of the reclassified Embedder/Bucketizer/Normalizer. All seven named. Fifteen more emerged from walking tech-arch §3 (repo layout) and §15 (interfaces): PhaseZeroProbe, ChannelFetcher, FeaturePipeline, CausalNormalizer, ReturnBucketizer, MarketStateEmbedder, ChannelMixerEmbedder (ablation variant), PriceSpaceLLM, BaselineModel, PriceSpaceDataset, Evaluator, CostCalibrator, SimulatorPolicy, SimulatorCostModel, ConfigResolver, ExperimentLogbook, TestLookGuard, WandbTracker. Plus ProcessRunner (the harness/main entrypoint of every script) added after a Step-7 halt-condition scan surfaced SESSION_INIT and SESSION_COMPLETE as orphaned.

**Every tag has an emitting operator.** 46/46. Step 7 halt condition on orphan tags: PASSES.

**Operator count 24 vs tag count 46.** Well under the operator-count > tag-count over-decomposition halt.

**Dual classifications recorded.** NormalizerState (Layer 0: frozen fit-state file; Layer 6: produced by CausalNormalizer). BucketStats (Layer 0: frozen fit-state file; Layer 6: produced by ReturnBucketizer). MarketStateToken (Layer 0: runtime output vector — not frozen file; Layer 6: produced by MarketStateEmbedder or ChannelMixerEmbedder). Session (Layer 0: trading-session entity; Layer 3: session stratum).

### Layer 7 — Evidence (39 constraints)

**Stratum coverage clean.** Every incident tag has a diagnostic_required constraint. Every summary tag has an outcome_required constraint. No tonal constraints — the tone canon in WORKING_AGREEMENT targets CLI stderr, not signal payloads.

**Frozen-artifact contract.** Explicit for BUCKET_STATS_WRITTEN, NORMALIZER_STATE_WRITTEN, SPREAD_SCALER_WRITTEN, KAPPA_WRITTEN. Each named file is write-once; downstream operators read from it; nobody recomputes. Per Addendum D1 (the crop-shipped-wrong bug): the paired "any consumer reads from this file, never recomputes" test is authored alongside every frozen artifact.

**Training-only-fit constraint.** BUCKETIZER_FITTED, NORMALIZER_FITTED, REGIME_LABELS_FROZEN, COST_CALIBRATION_FITTED — all fit on the training window only. Val and test never inform the fit. This is what makes vol-normalized returns scale-invariant across regimes without contaminating the target's tokenizer.

**Load-bearing config invariant.** CONFIG_RESOLVED.lambda_risk MUST be present. Absent value fires CONFIG_VALIDATION_FAILED at Pydantic load. Per tech-arch §11.3 ('A run without an explicit lambda_risk in its resolved config fails registration') and BLACKBOARD Deferred (Step-8 trigger fulfilled).

**Test-look cardinality.** sum(TEST_LOOK_REGISTERED per vocab_version) ≤ 3. Enforced both structurally (pre-commit hook) and at runtime.

**Sharpe reporting invariant.** sharpe_point always accompanied by sharpe_se on the same SIM_RUN_COMPLETED emission. Per product-spec §"Statistical honesty: the gates need confidence": "Every Sharpe number appears as Sharpe ± SE."

## Conventions worth naming explicitly

**Ambient-stratum tags are pointers, not payloads.** BAR_PROCESSED carries only `timestamp`; ALIGNMENT_ROW_EMITTED carries only `timestamp` and `missing_channels_count`. Where they fire tells the story; what happened at that firing lives in the paired artifact (the aligned parquet row, the checkpoint tensor, the metrics JSON). A Reviewer at sprint 15 reading `logs/sim-2026-11-15/signals.jsonl` and finding only `BAR_PROCESSED  t=...` for hours of trace should read that as normal: the semantic content sits one layer over. Per reviews/vocab-0.1-coverage-review.md finding 8.

**Domain-lifecycle strata are asymmetric.** `align_run` and `sim_run` are domain-lifecycle strata with their own boundary tag pairs (ALIGNMENT_RUN_STARTED / ALIGNMENT_RUN_COMPLETED, SIM_RUN_STARTED / SIM_RUN_COMPLETED). `train`, `eval`, `probe`, `calibrate` are not — they open and close with SESSION_INIT / SESSION_COMPLETE bearing `run_kind`. The reason: align_run and sim_run carry persistent attributes (date range, channels, checkpoint_step, cost_calibration_run_id) that downstream reads look up rather than re-parse from SESSION_INIT on every per-bar tag; the other run kinds do not. The consequence: no analogous cadence check on WINDOW_SAMPLED bounded by a `train_run`, no `allowed_set` sub-scope inside a training process. If a training-phase distinction (warmup vs main, epoch 0 vs epoch N) ever becomes load-bearing, `train_run` gets promoted to a domain-lifecycle stratum with boundary tags matching the align/sim precedent — a v0.2 candidate. Per reviews/vocab-0.1-coverage-review.md finding 6.

**Incident-halting asymmetry.** Incidents split on whether they name a correctness gate. `MANIFEST_STALE_OR_MISSING` and `TRAINING_DIVERGED` both trigger `forced_next → SESSION_COMPLETE` — the pipeline cannot produce a valid artifact if the manifest is stale or the loss is NaN. `WANDB_UPLOAD_FAILED`, `INGESTION_CALL_RETRIED`, and `FEATURE_COMPUTATION_FAILED` do not halt: they degrade observability or completeness but do not invalidate the run. The Layer-5 forced_next rules encode the distinction; the six incident tags do not all share a halting policy by design. Per reviews/vocab-0.1-round-5-review.md finding 4.3.

**FEATURE_COMPUTATION_FAILED downstream consequence.** The tag is a diagnostic; the downstream row carries `missing_mask__{channel}` = True for the affected channel, re-using AS_OF_JOIN_MISS semantics. Systemic failures — many features failing for one channel across many bars — surface via `CHANNEL_REJECTED` at the next probe run. The current pipeline does not halt on individual FEATURE_COMPUTATION_FAILED firings; incidence counted and reported per run summary via the Layer-7 `expected_count` constraint. Per reviews/vocab-0.1-round-5-review.md finding 4.2.

**Pairing cardinality 1:N is admitted.** BOOTSTRAP's seed examples use 1:1 and 1:2 pairing invariants. This vocabulary introduces one 1:N pairing at Layer 4: `CAPACITY_SWEEP_COMPLETED` ↔ N `SIM_RUN_STARTED / SIM_RUN_COMPLETED` pairs, one per size the sweep tested. Named explicitly so a future Reader does not read the cardinality as a typo. Per reviews/vocab-0.1-round-5-review.md finding 2.2.

**Sweep-as-entity: signal-based, not entity-based.** The model-size sweep, context-length sweep, and capacity sweep are first-class experimental deliverables. Each per-sweep-point run is a TrainingRun or a SIM_RUN with its own run_id; the sweep itself is a driver script that loops. v0.1 handles the sweep result with the summary tags CAPACITY_SWEEP_COMPLETED (already in the vocabulary) and — for v0.2 — analogous MODEL_SIZE_SWEEP_COMPLETED and CONTEXT_LEN_SWEEP_COMPLETED. No `SweepRun` entity added at Layer 0: the reconstruction from per-point runs is cheap, and the tag holds the summary the report needs. If Sprint 15's Report Reader finds the reconstruction friction real, promote to a Layer-0 entity in v0.2. Per reviews/vocab-0.1-coverage-review.md finding 7.
